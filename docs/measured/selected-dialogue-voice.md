# 对话伙伴切换为用户选定的 Step 女声

用户在[四段试听](dialogue-voice-audition.md)后选择
StepAudio 2.5「气质温婉」女声。此次将该声音接入独立个人语音小工具，
没有修改儿童课堂、文章音色复刻接口或模型配置文件。

## 当前行为

- 对话文字仍由本机 `vlm.studio` 生成；转写仍为本地 Whisper。
- 伙伴的问题通过 `stepaudio-2.5-tts` 的 `audio/speech` 朗读，音色为
  `elegantgentle-female`。语气指令、速度 1、24 kHz WAV 与获选试听一致。
- 页面显示所选模型、音色和云端文字发送说明，增加独立问题播放器。
  不再加载共享浏览器朗读模块，失败时保留文字、提示显式重试，不切回系统声音。
- 后端只接受本会话内由服务端生成的助手问题编号，不能将任意输入或用户原话编号
  直接交给付费 TTS。成功的音频按问题缓存在会话内，重复请求不再次合成。
- 页面也缓存本次问题音频，重听不再请求服务器。开始录音、播放参考音频或结束
  会话时停止问题播放；迟到的合成结果不能自动在录音期间或下一次会话中播放。
- 自动播放受阻时保留原生播放器和重听按钮。结束时清理前端 Blob URL 与后端缓存；
  后台闲置过期仍按原有 30 分钟规则清理会话。
- 新版在 `http://127.0.0.1:7270/` 运行并已打开。没有重启或刷新原 7050／7250 会话。
  旧服务不会热加载新的后端路由，应使用新版地址继续测试。

## 验证

- 后端 `tests/test_voice_lab.py`：24 项通过；模型均为模拟，HTTP 部分为真实本机服务。
  包括选定参数、Unicode 括号处理、错误脱敏、失败不自动重试、问题编号限制、
  缓存、跨会话隔离、结束时清理以及迟到结果不能恢复已结束会话。
- 页面 `tests/page/voice-lab.test.mjs`：6 项通过，包括重听复用、录音打断、
  新旧会话交错、显式失败重试和自动播放被拒绝。前端语法检查通过。
- 实际接口：独立验证会话使用前次公开合成的 Qwen 试听作为输入；没有读取用户录音。
  完成双份本地转写、真实本地对话、Step 追问合成、重复读取与会话结束。
  转写 0.32 秒，对话文字生成 3.81 秒，语音合成请求 6.347 秒，输出 7.48 秒。
  再次读取同一问题约 0.001 秒且字节一致。不是流式首音或并发基准。
- 浏览器通过页面开始按钮执行真实对话语音请求，问题播放器 `readyState=4`，无媒体错误。
  点击重听后页面显示「已缓存，重听无需再次生成」。没有触发麦克风录音或清除在用页面。
- 实际验证产物位于被忽略的 `outputs/voice-audition/` 目录下，
  包括公开测试产生的追问 WAV 和不含用户文字的耗时记录。

## 后续：男女声设置与本地部署核验

用户另要求加入「温柔男声」，放入设置，同时询问 StepAudio 2.5 是否能本地部署及性能。

- 工具顶部新增「设置」→「语音设置」，两项为气质温婉女声与温柔男声。
  允许的 ID 与显示名称以 `StepFunDialogueVoice.voices` 为唯一服务端来源；
  页面从状态接口读取选项，后端也校验 ID，不允许任意自定义音色请求。
- 浏览器只持久保存所选音色 ID，按当前站点记忆；不保存录音、文字或凭据。
  未保存偏好时仍默认为此前选定的女声。本次演示页已经选择并记住温柔男声。
- 聊天中「保存并重听」会改用所选声音朗读当前问题，后续追问也使用该声音。
  取消设置不修改选择，正在录音或处理回答时禁用设置。
- 前后端缓存均按「问题编号＋音色 ID」区分。切换声音时停止旧播放器并使迟到结果
  失效；切回成功生成过的声音复用缓存，不更改样本、转写、对话历史或文章复刻。
- 7290 新版已启动并打开；7280 为其他在用服务，未操作。
  未重启或刷新旧语音测试页。本次浏览器验证仅刷新了尚未开始会话的新版空页面。
- 后端专项测试 **26 项通过**；页面模块测试 **8 项通过**，前端语法检查通过。
  新增男女声参数、未知音色拒绝、同问题不同音色缓存隔离、迟到女声不得覆盖男声、
  切换后样本及历史保持一致的对照。
- 浏览器真实保存男声并重新加载空页面，确认偏好保留；开始会话后男声开场返回
  7.08 秒音频，页面显示等待 6.3 秒。切到女声，7.08 秒音频等待 5.1 秒；
  两者均 `readyState=4`、无媒体错误。再切回男声显示缓存命中，播放器进入播放状态。
  此次只合成公开固定开场，没有上传用户录音，也没有调用文章音色复刻。

### 部署与性能结论的证据边界

截至本次核对，所核对的 StepAudio 2.5 TTS 官方模型页和接口文档提供云端调用。
检索官方 GitHub／Hugging Face 来源，未找到 2.5 TTS 可下载的官方权重或公开自部署方案。
因此不能承诺把当前 2.5 模型和 `wenrounansheng` 预设音色原样搬到本机；
是否提供商业私有化部署，需要官方确认。这不是「所有 Step 语音模型都不能离线」的结论。

官方开源 Step-Audio-EditX 是不同的 3B 模型，要求 NVIDIA CUDA，已测试 Linux／L40S；
12 GB 是临界显存，官方称 16 GB 更稳妥，另有量化和节省内存路径。
当前 Mac 不能直接按该官方 CUDA 方案运行；Spark 上也未做此模型的兼容性或延迟实测。
这些硬件数据属于 EditX，不能套到 2.5 TTS。

温柔男声此前同句试听为 4.737 秒请求、6.32 秒音频；本次开场为页面等待约 6.3 秒、
7.08 秒音频。均为单次整段合成请求，含网络，不能视为稳定吞吐或首音延迟。
完整对话还要加本地转写和文本回复时间。
官方 WebSocket 文档特别提示 2.5 流式合成效果可能低于非流式；
当前仍使用用户认可的普通 HTTP 合成方式，本次不为降低等待时间而切换流式。
