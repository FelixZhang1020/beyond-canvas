# 开发看图回应切换到在线 Qwen

用户明确要求先使用在线 Qwen3-VL-8B-Instruct 改善开发体验。

## 配置范围

`studio/profiles/local.yaml` 的 `vlm.studio` 从本机 Step3-VL-10B 改为
OpenRouter `qwen/qwen3-vl-8b-instruct`，参数与现有 `cloud` 插槽一致，
`max_tokens: 4000`。沿用私有配置中的 `OPENROUTER_API_KEY`。
在线模型能力与入口见 [OpenRouter 模型页](https://openrouter.ai/qwen/qwen3-vl-8b-instruct)。

只有这个模型插槽的配置值发生变化。StepFun 安全筛查及独立判卷、
Replicate Klein 图片编辑、本地素描几何、转写与 3D 均保留现有配置。
`spark` 配置未改；本次不验证离线部署或 Spark 性能。

## 验证证据

- 配置解析确认仅 `vlm.studio` 改值，与 `cloud` 对应插槽一致，构建结果为
  `OpenRouterClient`；`spark` 与改动前快照一致。
- 现有插槽、OpenRouter 适配、课堂与 HTTP 服务测试：47 项通过。
  首次运行有 12 项被沙箱禁止绑定本地端口，允许本地端口后重跑通过。
  这些测试使用模拟模型，不是云端推理证据。
- 在 `http://127.0.0.1:7280` 启动 `local` 配置，通过真实课堂 HTTP 请求和
  事件流完成一次中文彩画开场。输入是程序从空白画布绘制的房子和太阳，
  不含用户原画或私人文字；调用真实 Qwen 和现有 StepFun 检查服务。
- 安全筛查 3.676 秒，回应生成与质量检查合计 10.257 秒；从提交反馈请求到
  完整 `done` 事件为 **13.965 秒**。返回观察文字和问题，适用规则无失败，
  事件中没有修复重试。测试课堂结束后清理了临时图片与该课堂记录。

原先计划使用用户提供的狮子画实测，自动审批因该具体私有图片发送到
OpenRouter 和 StepFun 的授权范围未确认而拦截，未执行上传。随后改用
程序测试图。不能把本次 14 秒与此前原画的 70–83 秒当作同图对照，
也不能从单次请求承诺持续延迟或复杂原画速度。

无内容的耗时摘要、测试输出和本次前置配置快照保存在 Git 忽略的
`outputs/qwen-dev-switch/`。不保存模型回应正文。

## 配置联动修复

后续代码审查发现两个依赖旧配置的错误，用户授权修复：

- 评测报告此前按 `local` 这个名字，把在线 Qwen 标为设备实际运行的模型。
  现在显示生成与判卷各自的模型、服务商，并将实际解析的生成模型与 `spark`
  配置中的课堂目标比较；即使模型名称相同，也明确说明没有验证硬件。
  开发评测默认仍使用 `local`；无法读取 Spark 目标时，仍保留生成来源信息。
- 成人语音工具此前读取 `vlm.studio` 的 Qwen 名称，却固定构建本机 Step 客户端。
  现在新增并读取独立的 `vlm.voice_lab`，使用本机 Step3、7100，保留普通对话模板，
  不使用素描的 assistant prefill。配置为非 llamacpp 服务商时明确拒绝启动该客户端。
  课堂看图仍走在线 Qwen；语音对话不会因此跟随切到云端。
- 模型状态板的相关测试改为检查实际本地的素描与成人语音插槽，并同时检查
  在线 Qwen 与 StepFun 的来源、无本地占用信息及不探测云端服务的行为。

验证：相关 Python 测试 **85 项通过**；全量默认 Python **674 项通过、8 项 live
未选中**；页面 **93 项通过**，在临时副本重建页面与工作区成品一致。
两项关键回归测试在独立进程中临时替换为修复前实现，均在预期断言处失败，
随后进程退出，未回写工作区。没有关闭或跳过原先失败的检查。

这些是配置、模拟请求和本机测试服务验证，没有新增付费模型调用，未重启在用的
个人语音会话，也不代表 Spark 实机验证。测试输出保存在私有忽略目录
`outputs/review-fixes/`。计数覆盖共享工作区其他功能，不是本次新增测试数。
