# Step 3.7 Flash 职责复核验证

范围：三方案共用客户端的独立请求复核，不是完整课堂质量验收。

## 已实现

- 对话使用 `vlm.studio`，创作单独使用 `vlm.creation`；复核使用 `vlm.director`。
  各客户端不保留上一次请求的消息。推理档位由方案分别配置。
- 草稿先做长度／故事结构和图片顺序检查，再发独立语义复核请求。
  复核只接受布尔 `ok` 和数组 `issues` 的 JSON；只有 `ok=true` 且 `issues=[]` 通过。
- StepFun `finish_reason=length` 即使带有完整外观的 JSON 也拒绝，空正文仍保留原诊断。
- 创作与复核预算均为 12000 token 上限，包含隐藏推理；不是实际用量。
- 图片选择按具体模型隔离缓存、计费和请求，失败不向另一模型重试。

## 离线控制

`tests/test_role_reviews.py` 覆盖正常、异常、矛盾和错误类型输出，创作／复核角色隔离、
双图片模型缓存及计费、未知选择、失败不自动使用备选；`tests/test_stepfun.py` 覆盖各档位
实际请求字段、请求间无历史泄漏及截断拒绝。模拟结果不作为真实语义能力证明。
