## 本机内存事故

用户报告内存被耗尽。此前 `prepare_viewer.py` 正在加载 TRELLIS.2 GLB 并统计连通块；
该进程最终退出码为 137，未生成 TRELLIS.2 的预览统计或页面网格。
事故现场没有记录完整峰值或系统终止日志，退出码本身不能单独证明 OOM 的具体触发点。

静态排查找到高风险路径：`mesh.split(only_watertight=False)` 会实体化所有子网格；
当前 trimesh 4.12.2 的 `TextureVisuals.face_subset → copy → PBRMaterial.copy`
会为子网格复制纹理图片。大量碎片可将一份材质放大为很多份。
旧代码本来只需要连通块面数，却执行了这些复制及默认的小孔修复。
原始 GLB 约 6.37 MB、98,428 面、136,826 个含 UV 接缝的顶点，并非文件本身巨大。
上述是与事故相符的代码证据，尚未通过重跑旧路径复现，也不会再次冒险复现。

处理措施：

- 确认计算进程已不在运行，停止本次 7330 预览服务。未主动终止其他项目服务。
- 使用 `skip_materials=True` 只加载几何；连通块改为稀疏标签统计，不实体化或复制子网格。
- 增加文件、访问器和几何规模检查，以及独立进程 RSS 监控、45 秒墙钟／CPU 限制。
  监控每 0.1 秒检查，阈值 768 MiB；它不是内核级地址空间硬上限，存在采样间隙。
  macOS 上尝试设置地址空间限制返回 `ValueError`，未谎称获得了硬内存隔离。
- 通过小任务与超限控制验证监控：2 MiB 分配通过；64 MiB 分配在 32 MiB 阈值下
  被终止，观察峰值约 80 MiB。另验证正常脚本入口在导入网格库之前必经监控父进程，
  成功与失败返回码均正确；这些是保护流程测试，不是原始网格复测。
- 页面取消自动预览；仅点击时加载单个网格。移除原来一次加载所有网格的 `data.js`，
  保留小型元数据，已生成网格用流式文件复制包装，不运行几何转换。

真实 TRELLIS.2 文件的修复后复测被自动审批拒绝，理由是担心内存保护没有包裹命令。
拒绝后没有重跑。已进一步用小型控制验证入口确实先调用监控；仍没有把这项控制
描述成真实文件通过。最后一次系统查询报告约 80% 可用内存，所有本次测试进程均已停止。

当前试验暂停：TRELLIS.2 效果未验收，Pixal3D 仍缺 GPU 配额／登录，不能给出三款排名。
恢复时应先审阅修复与资源保护，以受限方式验证现有下载文件；无需再次付费生成。

**用户后续指定优先在线：** 本地转换继续暂停，不因已增加保护而自动恢复。
已使用 Replicate 已完成预测的在线结果页查看 TRELLIS.2，页面明确显示 A100 80 GB、
Succeeded，并成功显示苹果和梨的带材质网格。该角度下表面高光很强；尚未完成中性
材质、原始视角对齐或重新摆灯的质量验收，因此仍不能给出三款效果排名。
此次只查看现有结果，没有重新提交生成或新增推理费用。在线页面的浏览器显示仍
在本机渲染，与在本地运行 TRELLIS.2 推理或进行网格转换是不同环节。

## 哑光材质修正

用户指出在线水果模型光泽过强。读取原始 GLB 的小型 JSON 块发现：材质的金属度与
粗糙度系数均为 1，同时使用 `metallicRoughnessTexture`。贴图与系数相乘，因此不能
只凭金属度系数为 1 就推断整张表面都是金属，也不能只把粗糙度系数设为 1 来消除
贴图里的低粗糙度区域。

在[官方 model-viewer 编辑器](https://modelviewer.dev/editor/)通过页面的 Edit Snippet
载入已经生成的 Replicate 文件地址，使用材质面板将金属度设为 0、粗糙度保持 1，
移除金属度／粗糙度贴图，保留基础颜色贴图。DOM 核对滑块实际值为 0、反光贴图为空；
浏览器中旋转查看了前后角度，原来的大块镜面亮斑消失，苹果凹口、两根果梗与颜色纹理
仍可见。使用中性环境光和 neutral 色调映射；该编辑器预览仍由浏览器渲染。
没有点击 Deploy Mobile，没有重新上传原图或提交生成任务。

独立文件保存为 `outputs/model-3d-bakeoff/trellis2/model_matte.glb`（6,365,060 字节），
原始文件保留。保存只用标准库修改 JSON 材质字段，其余块按 64 KiB 流式复制；未导入
网格／数值库、解码图片或运行模型。重新读取文件验证改动仅限预期材质字段，所有后续
二进制块的 SHA-256 与原件一致，所以几何、法线、UV 和纹理数据没有改变。
核对结果保存在同目录 `matte-report.json`。在线预览使用相同设置；因浏览器扩展的
本地文件权限未开启，没有把保存后的文件重新导入在线编辑器。

原始 GLB 的在线验证报告另有 5 条零长度法线错误，以及 bufferView target 缺省提示。
本次材质修正保留这些原始几何问题，不将哑光预览当作模型格式、任意摆灯、完整形状或
课堂集成验收通过。没有恢复之前的本地转换，也没有新增推理费用或 Spark 性能实测。

## 官方参考及 Spark 边界

- [TRELLIS.2](https://github.com/microsoft/TRELLIS.2)：官方要求 Linux、NVIDIA 至少 24 GB 显存。
- [Hunyuan3D 2.1](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1)：官方列出形状约 10 GB、纹理约 21 GB、合计约 29 GB；不是本次测量。
- [Pixal3D](https://github.com/TencentARC/Pixal3D) 与 [官方演示](https://huggingface.co/spaces/TencentARC/Pixal3D)。
- [Replicate 价格](https://replicate.com/pricing)：本次托管 A100 80 GB 为 $0.0014/秒、L40S 为 $0.000975/秒。
- [DGX Spark 硬件](https://docs.nvidia.com/dgx/dgx-spark/hardware.html)：128 GB 统一内存、273 GB/s。

CPU 端材质复制同样会占用 Spark 的统一内存；GPU 模型标称显存需求并不能涵盖整个
加载／后处理／浏览器流程。本次没有 Spark 峰值、延迟或 ARM64／GB10 扩展兼容性实测。
