# FLUX.2 Klein 4B 课堂动作关键帧接入

用户先要求保存评测，然后选择当前功能使用
FLUX.2 Klein 4B。此前已授权这两张画的 Replicate 在线处理。当前继续使用在线版本，
未下载本地权重，也未在 DGX Spark 实机运行。

## 当前行为

`painting-to-animation` 现在经 `Conversation.animate` 调用 `image.edit`，不再用
Step3-VL-10B 生成动作计划。图像编辑器产出一张新的动作关键帧；原画和生成图并排显示，
窄屏上下排列，导出保存生成图的 PNG。界面明确说明这是静态画面，还不是连续视频。
旧局部变形播放器仅保留兼容，不能把它的旧验收结果当作本路线的验收。

三套配置 `local`、`cloud`、`spark` 的 `image.edit` 均为 Replicate
`black-forest-labs/flux-2-klein-4b`，固定到七模型评测成功的版本
`8e9c42d77b10a2a41af823ac4500f7545be6ebc4e745830fc3f3de10de200542`。
参数为 `go_fast=false`、`seed=42`、`aspect_ratio=match_input_image`、
`output_megapixels=1`、PNG。适配器把单张原画包成平台要求的 `images` 数组；
单改模型名而保留 Step1X 的标量图片字段不能正确切换。

输入先通过现有安全检查，生成图也使用现有安全服务检查。安全通过仅意味着准许展示，
不证明改对了角色或保留了所有细节。当前 local 的安全服务仍是在线 StepFun；
没有让 Step3 接触本轮动画输入，也没有改变普通点评或素描重建使用的模型。

## 资源、计量与失败处理

- 一次只运行一个图像生成任务；其他平板得到忙碌提示。输入长边 1024，输出约 1 MP。
- 下载使用独立、无 API 凭据的 HTTP 客户端，只接收 Replicate HTTPS delivery 主机，
  不跟随跳转；12 MiB 下载、450 万解码像素、1280 输出长边上限。规范化后移除元数据。
- 输入和话语未变时复用已通过检查的结果。失败不会由 Harness 自动重新提交付费任务。
  300 秒配置是客户端等待上限，不能保证断网后已经接受的云端任务自动取消。
- 媒体计量进入同一阶段记录。按当时的公开单价与响应中的输入／输出 MP 数计算估价，
  本轮媒体约 $0.002/次，安全模型另外计量。这是估价，不是 Replicate 账单。
- 私有输入、生成图及供应商访问链接不写入过程账本。结束课堂移除原画、缓存和响应流。
- 无新运行依赖、无本地 Klein 权重；当前在线路线不占用本机 GPU 做图像生成。
  Spark 本地推理耗时和统一内存峰值仍未测，配置离线检查会正确报告 image.edit 需要网络。

## 实测与观察

使用之前授权的同两张画、中文动作要求，通过真实画室页面的上传和主按钮，完成了两轮
共四次 Klein 生成。两轮都测试导出和原输入再次打开；后者走缓存。没有自动重试生成。

| 版本 | 狮子图完整等待 | 城堡图完整等待 | 缓存再次打开 |
|---|---:|---:|---:|
| 初版通用提示词、默认随机种子 | 25.707 秒 | 47.117 秒 | 0.074–0.082 秒 |
| 收紧局部编辑提示词、seed 42（当前） | 27.547 秒 | 32.806 秒 | 0.070–0.075 秒 |

这里的完整等待包含输入／输出安全检查、上传、生成、下载和界面响应，不能与七模型评测
的单次 `predict_time` 混用，更不能当作 Spark 推理速度。图像分别为 1024×1024、1216×848。

初版狮子图主要改变了右侧小狮子，城堡图丢失了多只老鼠。收紧提示词并固定种子后，
大狮子的抬头更接近要求，城堡士兵抬手且其他角色大体保留。仍有非目标区域的笔触修饰，
士兵动作幅度也不完全等于“一只手”；原画保真和任意中文动作泛化未验收。
两轮同时改变了提示词和种子，不能据此归因到单一因素，也不是统计评测。

桌面 1440×1050、手机 390×844 的对照页均检查过，无横向溢出和浏览器脚本错误；
保存文件能作为 PNG 解码，减少动态效果模式下也保持静态对照。

代码验证：默认后端测试与前端测试见文末最终计数。它们包含模拟客户端与本机服务检查，
与上述四次真实图像生成分别记录。未进行 Spark、真实课堂或任意作品的质量验收。
