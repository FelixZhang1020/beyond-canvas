# 石膏几何体与水果

用户提供一张球体、方体与梨的素描，要求继续优化其识别和 3D 光影效果。
修复前，同一个本地 Step3 模型在开放看图时能认出梨，但 3D 提示词只允许基础几何体，
导致返回 `sphere / box / sphere`，页面错误地以成功状态显示椭球替代的梨。
该基线识别与重建约 8.07 秒，独立开放识别约 4.96 秒；均为真实本地模型调用。

## 当前实现

3D 定位明确区分 `box / sphere / cylinder / pear / apple / orange`。水果先取果身、
可见果梗及梨颈的区域框，再由 [sketch.py](../../studio/making/sketch.py) 转成有范围约束的比例。
[still_life.py](../../studio/making/still_life.py) 按这些测量值建立圆截面的近似表面和独立果梗。
果身宽度、梨颈比例和物体位置随图片变化；看不到的厚度、精确外轮廓及果梗倾角仍是估计。
不把原图阴影烘焙成贴图，不使用预制梨模型替代定位。

相同透视拟合用于三件物体，整体缩放时同步变换相机与物体，保留构图。
水果混合场景返回 `parametric-still-life` 网格，与头像共用现有 WebGL 三角形及阴影渲染器。
球体、方体、梨和果梗之间可以产生遮挡及投影；转动、调光、原画对照和缓存沿用课堂入口。
这条路径不调用 TripoSG，也没有新增模型权重、生产依赖或付费服务。

## 真实图像验证

使用用户本轮上传的同一张私有素描，1536×1024，输入缩至长边 1024。
视觉模型为本机 Step3-VL-10B Q4_K_M，使用已有 `vlm.sketch` 配置。
私有原图、定位、场景及模型输出只保存在忽略目录，不纳入本报告或 Git。

首次尝试直接输出多行轮廓点时，模型把三元坐标误写成四元框，结果未采用。
改用原生区域框后，实际生成了可辨识的梨颈、果身和果梗。复测暴露过枚举值带说明文字、
漏掉果梗字段两个问题：提示词改为精确枚举，并对缺失水果字段增加最多一次补充识别。
补充后仍缺失或坐标无效会失败；明确不支持的物体、普通无效 JSON 和头像建模不会因此重试。

| 最终课堂流程 | 本机实测 |
|---|---:|
| 安全筛查 | 9.585 秒 |
| 识别与重建 | 6.825 秒 |
| 完整服务阶段合计 | 16.410 秒 |
| 同一作品再次生成，缓存阶段 | 0.004 秒，0 token |

独立调用中，识别完成后的 CPU 拟合及网格建立约 0.026–0.039 秒。
三物体场景为 2,240 顶点、4,432 三角形。这里的 CPU 时间不包含看图和安全筛查，
缓存时间也不包含浏览器显示时间；本机存在其他运行服务，不是隔离硬件性能基准。

在真实 7070 课堂验证了：上传原图、筛查、重建成功、窄屏查看原画、转动视角、
灯从左移右及升高后的明暗与地面投影变化、复位、再次生成命中缓存；浏览器无脚本错误。
原有三几何体素描仍走 `geometric-approximation`，单头像仍被识别为 `head`，
这两项分类／几何回归使用真实本地模型；本轮没有重新运行耗时的头像网格推理。

测试课堂将安全与视觉都显式接到本地 Step3，本轮没有将原图送往云端。
常规课堂其他插槽仍按各自配置运行，不能据此宣称整个产品全离线。

## 资源限制和验证范围

- 最多六件物体；40 个圆周采样、32 个果身高度采样。程序检查中六个梨（含果梗）
  低于 16,000 个三角形，仍受既有 60,000 三角形／8 MiB 的网格出口限制。
- 最多两次视觉调用，仅当已认出的水果缺少必要字段时才补充一次。每次输入长边 1024、
  最多 1500 输出 token。课堂重建仍串行，成功后缓存，不会反复调用模型调灯。
- 渲染沿用 100 万画布像素上限、六面 1024² 阴影图和按需绘制；相机转动复用阴影图，
  光源移动才重绘阴影，关闭释放 GPU 资源。
- 完整后端检查 **702 passed、8 deselected**；完整前端检查 **101 passed**；构建结构检查通过。
  计数包含共享工作区其他功能。新增测试覆盖部分坐标错误、误把带果梗的水果分为球、
  梨颈尺寸变化、无果梗、六水果预算、透视保持、课堂缓存，以及补充识别成功／失败两种控制。

本轮实际图像验收针对用户提供的梨。苹果和橙子已有分类与近似几何路径及程序检查，
未进行真实图像验收；香蕉、葡萄、多人物、头像与独立静物混合仍未支持。
水果背面和细节没有精确恢复，也未验证真实儿童画的泛化。
DGX Spark 实机、ARM64 环境和真实平板帧率尚未测试；本机时间不能当作 Spark 性能承诺。
