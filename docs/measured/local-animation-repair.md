# 保留原画的局部动画：修复与验证

用户明确选择“保留原画的局部动画”。这次完成的是
呼吸、摇摆、轻移等局部效果，不是走路、转身或视频扩散生成。

## 实际失败原因

1. 旧播放器抹掉矩形选区，以图像上缘的平均颜色填补，再平移裁片。
   两张输入都具有丰富背景，纸色填补没有成立的前提；它会留下色块、
   移动相邻对象，并在循环末尾突然跳回。结构检查不能发现这些视觉问题。
2. 本机模型健康接口正常；HTTPX 默认读取代理环境后返回 502，同一个
   地址关闭环境代理则返回 200。`LlamaCppClient` 现在对明确的回环地址
   直接连接，远程地址仍保留代理环境配置。
   [HTTPX 官方环境变量说明](https://www.python-httpx.org/environment_variables/)
3. 局部位置的模型判断并不可靠。第二张画的三个建议区域中，两个没有
   对准所命名的部位。因此不能把“JSON 合法”称为“动画内容正确”。

## 最终实现

- 使用原图纹理的连续网格变形，选区边界和图像边缘固定，区域中心运动。
  不删除画面，不补背景；每次动作回到原画。区域内的周边笔触也会轻微弯曲。
- 五种局部动作：breathe、sway、drift、rise、grow。旧 enter/exit 数据仍
  可读，但变为小幅局部平移，不再让角色消失。
- 老师可用“调整动作位置”拖出选区、切换动作，立即预览。调整保存在当前
  页面结果中；不写入服务端缓存，也不承诺跨重启恢复。
- Python 和浏览器都拒绝非有限数、错误结构、越界区域及过多图层；保留
  课堂安全检查。动作门槛只有确定性检查，没有故事语义或视觉分割保证。
- 同一课堂服务同时最多处理一个动画请求；额外请求返回已有 busy 提示。
  每张画只缓存一份成功计划，孩子的话改变时重新推理，结束课堂时释放。
- 页面离开、关闭或切换作品时停止动画，释放纹理、缓冲和 WebGL 上下文。
  隐藏页面和编辑区域时暂停。系统“减少动态效果”显示静态原画。
- WebM 导出使用当前画布和计划时长，结束或失败释放录制轨道。无法录制或
  减少动态效果时回退 PNG。浏览器导出实际生成了可解码的 VP8/WebM。

## 两张真实画的证据

原图由用户提供，仅用于本机检查。私有预览和测量文件位于忽略目录
`outputs/animation-repair/`，不进入仓库。预览默认选区经过人工核对，
并可切换“模型自动选区”，两者没有混称。

| 检查 | 结果 | 证明范围 |
|---|---|---|
| 本机 Step3-VL-10B，两次独立动作计划 | 89.410 s、89.979 s，均返回 3 区域且结构合法 | 真模型调用，排除安全检查；不是 Spark 测量，也不是完整课堂端到端计时 |
| 原始模型计划、Chrome WebGL，分别渲染两张画 | 所有像素不透明；起止帧完全相同；中间帧确实变化 | 实际浏览器像素检查；没有证明模型选区全对 |
| 强制 Canvas 2D，分别渲染两张画 | 同样通过不透明、首尾相同和运动检查 | 真实兼容路径；不是老旧平板验收 |
| 编辑器拖动选区、切换动作、播放 | 实际浏览器通过，位置按图像比例更新 | 画面没有 letterbox 坐标误差；不调用模型 |
| 页面按钮导出 | 1280×892、约 5.97 s、VP8/WebM，可解码 | 实际导出；不同浏览器可能回退 PNG |
| 关闭、快速换图、减少动态效果、强制低负载路径 | 通过 | 浏览器操作与针对性单元测试 |
| Python 完整默认验证 | 见下方最终复核记录 | 排除 live 收费测试；包含模拟模型及本机 HTTP 测试 |

低层绘制测量：当前 Mac 的 WebGL 绘制调用（含 `finish`）p95 约 0.2 ms；
Canvas 2D 提交 p95 约 0.4 ms。首次 WebGL 初始化约 467 ms，后续约 12 ms。
这不是整个浏览器帧耗时、功耗或总内存峰值，也不外推为 Spark 的帧率。

## Spark 约束

[NVIDIA 官方规格](https://www.nvidia.com/en-us/products/workstations/dgx-spark/)
列出 128 GB 统一内存、273 GB/s 内存带宽和 Arm CPU。统一内存容量不能
直接推导出视频生成或语言模型响应时间；标称 FP4 算力也不是该工作流速度。

本次动画路径不增加模型权重。生成计划继续使用已有 vlm.studio；播放在
观看设备完成（若浏览器运行在 Spark 本机，则共享其资源），不会让服务端
为每帧运行推理或发送视频。预算为：

| 项目 | 主路径 | 无 WebGL 回退 |
|---|---|---|
| 长边上限 | 1280 px | 640 px |
| 帧率上限 | 30 fps | 15 fps |
| 网格最长边 | 48 格 | 20 格 |
| 动作区域 | ≤3 | ≤3 |
| 额外动画模型权重 | 0 | 0 |

最大原图纹理约 6.25 MiB，网格数据低于 0.1 MiB；这些不是浏览器总内存。
原图解码、页面上的其他画、帧缓冲、驱动和导出编码还要占用内存。
模型侧仍有一次视觉编码和文本生成，其实际峰值不能由权重大小代替。

**剩余限制：首次自动生成仍约 90 秒，尚未达到两秒。** 本次保留现有
8000-token 上限；该 Step 模型会先推理，直接缩小上限可能得到空输出，
不能以截断回答换取“更快”。缓存命中和老师调整无需重跑推理。

到 Spark 后需用相同输入分别记录冷启动/热调用 p50、p95、统一内存峰值、
视觉模型与课堂其他模型共存状态、浏览器连续播放和导出的帧率及资源释放。
未在实机测得这些结果之前，不承诺课堂首次生成速度或总体内存预算已达标。
