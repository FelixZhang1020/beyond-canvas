# 素描立体场景与调光

本次修复把几何体素描接入课堂的 `sketch-to-3d` 请求，输出可交互的透视场景。
支持最多六个落在同一桌面上的方体、球／椭球和直立圆柱；页面保留原画对照，
明确标注这是近似重建。复杂器物、人物、动物、堆叠和悬空形体不在当前支持范围。
没有把通用单图网格重建、真实儿童作品泛化能力或 Spark 实机性能算作完成。

## 已确认的缺口

- 课堂 `BUILT` 原来只有点评和动画，未接入素描转 3D。
- 页面把 `turntable_url` 当预览图／视频，模拟实现只是把原照片左右压缩；没有三维几何和调光器。
- [早先的网格实验](sketch-to-3d.md)记录了浅色立方体缺失。
  [InstantMesh 源码](https://github.com/TencentARC/InstantMesh/blob/main/run.py)
  确认默认路径会移除背景，但“加遮罩就能解决所有问题”仍未经验证。
  本次几何课堂路径绕过抠图和网格扩散；没有声称修好了通用 InstantMesh 重建。

## 实现与可解释的限制

1. 沿用原有安全筛查。允许后，视觉模型只定位形体及圆柱顶面，返回 0..1000 的 xyxy 坐标。
   精细素描曾被入口拒绝；原判定提示限定“3–12 岁儿童画”，与按可见媒介判断的规则冲突。
   现明确按笔触、轮廓和纸纹判断，绘画水平不作为拒绝理由；照片、空白和有害图的拒绝规则保留。
2. Python 把坐标转为尺寸估计，用有固定迭代上限的透视拟合摆放形体。
   圆柱顶面的椭圆用于联合校准相机。椭圆长短轴比给出的是朝向顶面的观察射线，
   直接将其当作绕场景中心的相机俯角会让相机低于顶面；回归测试覆盖了这次发现。
   模型独立定位圆柱和顶面时，曾出现约 1% 图幅的边界差异。现在仅在误差不超过
   图幅 2% 且不超过物体最短边 10% 时合并外框，保留完整顶面比例；更大偏差仍拒绝。
3. 输出小型 JSON 场景。浏览器用 WebGL 对封闭几何体计算视线交点、表面法线和光线遮挡，
   包括物体之间、物体自身和桌面的阴影。原画明暗不贴到几何体上，因此不会锁死旧阴影。
4. 拖动视角、俯视图摆灯、点按桌面摆灯、位置／高度／亮度滑块、恢复初始状态和 PNG 导出。
   键盘可操作；小屏可切回原图。关闭时释放图形资源；不可用时保留原画并说明原因。

单张素描不能唯一决定背面和绝对尺寸。当前使用任意场景单位；背面深度按宽度估计，
方体初始旋转为 40°，没有可靠顶面时初始相机俯角为 25°。尺寸来自外框，不能保持每一处
手绘轮廓偏差，也不是设计中“学生精确网格与标准模型并排”的完整实现。
初始左上方灯是教学默认值，不是推断原画光源方向的测量结果。

## 本机模型验证

使用用户提供的方体／球／圆柱素描，本机 Step3-VL-10B，已有 llama.cpp 服务。
图片未加入版本库。最初让模型同时计算分数外框、比例和相机参数，出现了耗尽
4000／6000 token 仍没有答案，以及复制示例坐标的问题；这些尝试不算成功。

改为模型原生目标定位，并使用 llama.cpp 的 assistant prefill 后，一次定位调用实测
**6.77 秒、151 输出 token**，返回三种形体和圆柱顶面。后续 CPU 相机与几何拟合约
**0.13 秒**，场景不到 **1 KB**。这些数字描述单个样本和一次调用，不是吞吐量、P95
或课堂端到端等待时间，也不包含安全筛查。

`vlm.sketch` 是同一端点的请求别名，不是第二份模型。`assistant_prefill` 仅限这个别名，
反馈和安全的调用方式保持原样。服务可能把 prefill 原文带回，适配器只移除完全相同的
已发送前缀；空结果仍按失败处理。旧 llama.cpp 或别的模板必须再验证。

依据：[llama.cpp 服务文档的 assistant prefill](https://github.com/ggml-org/llama.cpp/tree/master/tools/server)，
[StepFun 对非思考模式的说明](https://huggingface.co/stepfun-ai/Step3-VL-10B/discussions/20)。
模型方未保证非思考模式的泛化质量，因此结构门槛和原画对照仍有必要；它们也不能证明语义识别必然正确。

完整课堂页面随后使用同一张图完成上传、筛查、定位、拟合、展示和再次打开：
安全阶段 **23.325 秒**，重建阶段 **2.900 秒**，两阶段合计约 **26.2 秒**（不包含
上传和浏览器展示时间）。再次请求成功场景为 **0 输出／输入 token、0.005 秒** 后端阶段。
测试服务把安全、定位都接到本机 Step3；这不是默认 `local` 配置云端安全路径的实测。
单独的空白纸真实模型对照返回 `empty`，耗时 6.95 秒；照片／有害图的拒绝及“两次看图”
仍由现有模拟测试覆盖，本次没有新增真实照片或有害样本评测。

三次额外本机定位结果起初都因顶面外框略超出圆柱而失败；按上述误差规则重放后，
全部保留三形体，最大外框拟合误差为 3.07% 图幅。没有通过自动反复调用模型来掩盖失败。

## DGX Spark 的实际约束

[NVIDIA 的移植指南](https://docs.nvidia.com/dgx/dgx-spark-porting-guide/overview.html)
说明 Spark 使用 ARM64 CPU，CPU/GPU 共用 128 GB 内存，带宽 273 GB/s。
不能把全部内存当独占显存，也不能把 FP4 峰值算力当浏览器帧率或单图生成速度。

本次落地的限制：

| 环节 | 已实现的上限／调度 |
|---|---|
| 模型输入 | 长边 1024；定位调用最多 1500 输出 token |
| 额外权重 | 复用已有视觉模型；此路径不加载 InstantMesh、SAM 或图像扩散模型 |
| 并发 | 同一课堂服务只接受一个进行中的 3D 重建；忙时明确返回 |
| 缓存 | 同一会话、同一幅画复用成功场景，不重复识别 |
| 几何 | 最多六个解析几何体；固定的 CPU 拟合次数 |
| 像素 | 单画布；DPR ≤ 1.5、宽度 ≤ 1440、总像素 ≤ 1,000,000 |
| 阴影 | 交互时每点一条遮挡射线，停手后最多四条；不加载阴影贴图或模型纹理 |
| 刷新 | 只在操作／尺寸变化时绘制；合并同帧操作；隐藏页面和关闭视图停止绘制 |

尚需到机验收：实际 ARM64 推理服务及 prefill 兼容性、完整安全服务、课堂并行负载下
的共享内存峰值、4K 显示时交互延迟和温度／持续性能。`spark.yaml` 中其他媒体与安全
服务的占位问题依然存在，本次没有把整个 Spark 配置宣称为可部署状态。

## 验证入口

- `tests/test_sketch.py`：输入范围、拒绝路径、顶面校准、透视、缓存、调用限额、安全顺序与真实本机 HTTP 事件流；模型使用测试回复。
- `tests/test_llamacpp.py`：prefill 只在选用时生效、精确前缀移除、空回答仍失败。
- `tests/test_modelboard.py`：同一端点同一模型的请求别名不误报端口冲突；其他服务抢占仍报错。
- `tests/page/relight.test.mjs`：场景约束、透视射线、摆灯投影、像素预算、双语和资源释放；图形上下文使用模拟对象。
- 浏览器直接检查实际 WebGL 画面：三个形体、转动视角、左右换光、物体投影、窄屏原图对照。

最终默认后端测试 **597 passed、8 deselected**，前端 **63 passed**；计数包含同一工作区
其他并行功能的测试。页面构建通过结构检查。默认测试不调用真实收费服务。

实际浏览器中检查了三个形体、右移灯后的左右明暗互换与交叉投影、原图对照和课堂缓存。
独立的实际 WebGL 验证页在 3840×2160 CSS 尺寸下使用 **1333×750** 帧缓冲，
换光与转动视角分别改变画布内容，WebGL 错误为 0；等待空闲及关闭视图后额外绘制次数均为 0。
浏览器同步计时只有 0–0.1 毫秒读数，不足以作可信帧率或 P95 性能结论，因此不用于 Spark 外推。
PNG 导出按钮已在课堂中触发；生成文件内容另由同一渲染模块的浏览器检查验证。
