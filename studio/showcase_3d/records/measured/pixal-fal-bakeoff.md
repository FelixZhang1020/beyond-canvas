# Pixal3D：fal API 两张素描实测

用户购买 fal.ai 额度并要求检查 `.env` 中的
`FALAI_API_KEY` 后，沿用此前两张图进行两次真实云端调用。**两次生成和 GLB 下载
均成功，两个成品已在浏览器旋转检查。** 没有本地模型推理、权重下载或网格转换。

## 凭据与调用范围

`FALAI_API_KEY` 已配置，真实提交成功验证了它可调用 `fal-ai/pixal3d`。密钥仅在
进程内读取并发送给 `queue.fal.run`，没有输出到日志、写入报告或放入网页。
当前没有 `FAL_KEY`；测试脚本直接读取用户指定的变量，课堂现有 `FalClient`
仍默认读取 `FAL_KEY`。本轮没有更改环境文件、生产 provider 或课堂模型选择。

每张图只提交一次；任务 ID 接收后立即保存。提交及服务端自动重试均关闭，开始
执行前的队列期限为 600 秒。实际两次均结束，没有本轮未完成的云端生成。
服务生命周期与时间含义依据 [fal 队列文档](https://fal.ai/docs/documentation/model-apis/inference/queue)。

## 外观结论

- **三几何体：可用候选。** 方块、球体、圆柱和主要遮挡均保留；没有可见多余大
  底板，方块顶面较平整。球面有少量不规则起伏，但没有此前免费网页预览中明显
  的规则多边形分面。圆柱边缘略软，侧面有轻微起伏。场景整体朝向与既有查看器
  默认坐标不同，接入地面和摆灯前仍需校准朝向与接地。
- **石膏头像：主体较好，但有多余碎片。** 去掉颜色纹理后，五官、耳朵、头部大
  切面、颧骨、下颌、颈部和底座仍能辨认，说明主要切面确实存在于几何中。侧后
  方可见一块脱离主体的小碎片，旋转时随模型改变位置；没有进行连通分量分析或
  清理。背面体积连贯，但没有真实扫描可用于验证背面是否准确。

观察使用 [model-viewer 编辑器](https://modelviewer.dev/editor/)，一次只显示一份约
3 MB 的 GLB。曝光 0.7、阴影强度 0、中性环境；临时设置 `#999999`、金属度 0、
粗糙度 1，并移除颜色和金属粗糙度贴图。几何体检查了前后、上方和侧面；头像检查
了原图附近角度及侧后、背面。两者约 `yaw=180, pitch=90` 对应原图方向。
浏览器预览修改没有写回原始 GLB，也没有验证点光源移动或实时阴影。

**本轮调整判断：Pixal3D 已从“受网页配额限制、缺少 GLB”变为真正可接入测试的
候选。** 几何体结果接近此前 TRELLIS.2 的可用水平；头像保留切面，但因多余碎片
仍建议保留 TRELLIS.2 为当前优先候选。两次单样本不能给出可靠的整体模型排名。

## 性能与验证边界

本机只做 HTTP、流式下载、哈希和有界 GLB JSON 检查，未创建大型几何数组或解码
贴图；浏览器承担常规显示。文件小不代表生成显存小。fal 没有提供峰值 GPU 内存，
没有在 DGX Spark 实测，不能把这次 27–31 秒处理时间当作 Spark 的性能。

检查通过：两个输入哈希、参数正常控制及非法分辨率／过小简化目标拒绝控制、两次
服务最终状态、文件容器头和长度、下载哈希、两份实际浏览器旋转检查。结果页仅做
静态内容和链接校验；此前本地网页自动化访问被自动审批拒绝，本轮没有绕过限制。
本轮只添加实测归档和文档，没有修改课堂业务代码，未运行应用完整测试套件。
