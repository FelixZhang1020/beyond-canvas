# 三张素描、四模型统一交互对比

用户要求将 TRELLIS.2、Pixal3D、Hunyuan3D 2.1、
TripoSG 对三张图的结果放在同一页面，并明确授权补齐水果生成和三份云端减面。

**现状：十二份原始生成全部归档，十份可在统一页面交互显示。** 几何体为四份；
头像、水果各三份。TripoSG 头像的云端减面因原始文件过大失败，水果原始文件
更大，未重复提交已知不满足大小限制的请求。两处保留真实状态和原始下载入口，
没有用别的模型、静态图片或旧平滑版本填充。

## 入口和交互

- 本机页面：<http://127.0.0.1:7135/>。
- 归档：`outputs/model-3d-bakeoff/comparison-three/`。
- 若服务已停止，在仓库运行 `python3 outputs/model-3d-bakeoff/comparison-three/serve.py`。
- 服务只绑定回环地址，按白名单提供页面、资源和十二份原始文件下载，不公开
  `.env`、调用报告、转存记录或服务器端原始路径索引。

三张原图切换；四窗同步或独立旋转、缩放；单窗放大；原图弹窗；哑光、表面朝向、
网格显示；统一方向光角度／高度；可选地面与真实投影。材质默认为非金属、粗糙度 1，
原始 PBR 贴图在加载器处跳过，不做本地纹理解码或写回修改。

每份模型按整体边界等比缩放并居中，只校准初始朝向，不清理底板和碎片。
因此底板很大的模型，其主体会显得更小。不是物理尺寸标定，也没有自动拟合每个
物体的接地点；Pixal3D 几何体的原始整体朝向／接地仍需进一步校准。

## 本轮真实云端调用

| 操作 | 结果 | 服务处理时间 | 本地归档 |
|---|---|---:|---:|
| Pixal3D 水果，fal 1024、seed 42、目标十万面 | 成功 | 27.632 秒 | 3,314,208 字节 GLB；99,443 面 |
| TripoSG 水果，Replicate 固定版本、50 步、seed 42 | 成功 | 64.305 秒 | 242,591,926 字节 OBJ |
| TripoSG 几何体 → Meshy，目标十万面 | 成功 | 77.413 秒 | 3,350,396 字节 GLB；98,295 面 |
| TripoSG 头像 → Meshy | 失败 | 未产出 | HTTP 422：`model file too large` |

- Pixal 水果请求：`01a079b2-bb9b-7513-837a-a2854962c2e2`；约 293.3 秒才观察到
  完成，含排队，不能将 27.6 秒当作端到端延迟。
- Tripo 水果请求：`vn3sjwy3dxrn80d0f6tt617j2g`；Replicate `total_time` 196.459 秒。
  原始文件超过第一次归档的 128 MiB 防护，随后只将流式归档上限改到 256 MiB，
  继续下载同一成功请求；没有重复生成，也没有在本地解析大网格。
- 几何体减面请求：`01a079c1-864d-7631-809d-d9fa43fe8a9a`；观察到完成 82.573 秒，
  含下载 86.44 秒。该 GLB 是 TripoSG 原始几何经 Meshy 减面后的**派生版本**。
- 头像失败请求：`01a079c3-2232-74e2-81b0-be94e32d5009`。

此前几何体直接提交 Replicate 临时链接被服务拒绝下载，随后按照官方 fal SDK
的 CDN v3 multipart 协议，用顺序 10 MiB 分块转存原始文件后成功。
头像转存 106,020,451 字节成功，但 Meshy 拒绝文件大小。原失败记录保留。
原始 OBJ 只进行流式下载、逐行计数和哈希检查，没有本地推理、减面、格式转换、
权重加载或贴图拆分。

云端减面支持的文件类型以 [fal Meshy API](https://fal.ai/models/fal-ai/meshy/v5/remesh/api)
为准；[Meshy 官方导入说明](https://help.meshy.ai/en/articles/9991884-what-3d-file-formats-does-meshy-support-full-export-list)
给出 100 MB 上限。头像实测错误和水果更大的原始文件是当前阻塞依据。

成功产出按公开单价及 Replicate 时长估算新增约 **$0.59**：Pixal $0.30、Tripo
$0.09003、一次成功减面 $0.20；**没有核对最终账单**。用户批准的上限估算为
$1.74，未完成的两次减面不记作已经成功或已支付。

曾提出本机逐行格式转换、256 MB 硬限制的备选方案，但本机 macOS 上
`RLIMIT_AS` 设置测试失败（`ValueError: current limit exceeds maximum limit`）。
已经向用户更正，**没有据此执行任何真实大文件本地转换**；不能把该上限写作已生效。

## 验证和外观观察

通过的检查：

1. 十份真实 GLB 的长度、SHA256、容器头、声明面数、内嵌资源检查。
2. 八个拒绝控制：路径越界、元数据超限、哈希错误、长度错误、无效 GLB、外部资源、
   超过 350,000 面、实际响应超过 16 MiB。路径／元数据错误在发请求前拒绝。
3. 本机 HTTP HEAD：页面、脚本、模型、原始下载可达；私有索引、调用脚本、转存
   报告和路径越界均拒绝，未下载大型原始模型做浏览器检查。
4. 新 HTTP 对比页的真实浏览器验证：十份显示模型都加载成功；三图切换、同步与
   独立键盘旋转、自动旋转推进和重置、单窗放大、材质切换、原图弹窗通过。
5. 方向光从 +60° 改到 −60° 后，表面明暗和投影方向实际改变；关闭阴影后
   renderer 贴图计数从 4 降至 0。几何体默认显示 4 份几何／0 贴图，切到水果为
   3 份几何／0 贴图。之前场景的资源没有在这些切换中累积。

加载串行，包括快速切换时尚未完成的解析；页面只有一个共享 WebGL 上下文，使用
四个视口。每份显示文件限 16 MiB、350,000 面；像素比最多 1.25，画布最多约三百万
像素；静止时按需绘制，自动旋转限制约 30 帧，后台暂停。计数不等于浏览器总内存
或 GPU 峰值；未做长时间压力测试、移动端实机测试或 DGX Spark 实测。

统一哑光下新增观察：Pixal 水果两主体和果梗完整，但表面有环带状起伏；TripoSG
几何体有不规则底片，球体较粗糙，圆柱底缘有起伏。TRELLIS.2 的水果和头像主体
较完整；Hunyuan 静物底板明显，头像可辨认但切面偏圆滑。该结论是这些样本的
视觉观察，没有三维真值，不构成总体模型排名或同硬件速度比较。

本轮仅新建独立比较归档并补充测量文档，没有修改课堂业务、环境变量或模型选择，
没有运行整套课堂测试，没有 commit、push 或公开部署。
